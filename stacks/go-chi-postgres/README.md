# Go 1.23 + chi + pgx + sqlc + testify

The minimal, idiomatic Go web stack. Stdlib `net/http` semantics via chi's router, direct Postgres access through pgx, type-safe queries generated by sqlc, tests via testify. No ORM, no DI framework, no surprises.

## Why these choices

- **chi over Gin/Echo/Fiber.** chi is a thin wrapper on `net/http`. Middleware signature is `func(http.Handler) http.Handler`, which matches the stdlib and every off-the-shelf middleware. Fiber breaks that contract.
- **pgx over `database/sql` + lib/pq.** First-class Postgres support, faster, better types. The cost: no driver portability, which this stack accepts.
- **sqlc over ORMs.** Write SQL, get typed Go. Refactors that change a query type fail to compile. The cost: no dynamic query building; complex search filters are still hand-written.
- **golang-migrate over goose / atlas.** Lowest dependency footprint, single binary, schema-as-SQL fits the no-ORM ethos.
- **testify over plain `t.Errorf` everywhere.** `require` and `assert` are widely understood and cut boilerplate. No `ginkgo`, no `gomega`.

## What to tune

- For a CLI or worker that has no HTTP surface, drop chi and use a `urfave/cli` or `cobra` entry point. Keep the `internal/` layout.
- If multi-tenant SQL is heavy, add `goqu` or `squirrel` for dynamic where-clauses alongside sqlc's static queries.
- Swap testify for `gotest.tools/v3` if a stricter assertion library fits the team.
- Add `wire` or `fx` only if the `Server` struct grows past 10 dependencies; below that, manual wiring is clearer.
