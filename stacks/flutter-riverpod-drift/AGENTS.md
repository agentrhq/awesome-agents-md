# AGENTS.md · Flutter 3.24+ · Riverpod 2 · Drift · go_router

## Stack

- **Dart:** 3.x with sound null safety. SDK constraint `>=3.4.0 <4.0.0`.
- **Flutter:** 3.24+ (latest stable channel; `fvm` recommended for pinning, `.fvm/version` is source of truth).
- **State:** Riverpod 2 (`flutter_riverpod` + `riverpod_annotation` + `riverpod_generator`). No `provider`, no `bloc` in the same tree.
- **Persistence:** Drift (formerly Moor): `drift` + `drift_dev` + `sqlite3_flutter_libs`. Codegen via `build_runner`.
- **Routing:** `go_router` with typed routes generated by `go_router_builder`.
- **Testing:** `flutter_test` (unit + widget), `integration_test` (E2E driven by `flutter test integration_test/`).
- **Lints:** `very_good_analysis` (strict). `dart format` (80-col by default; raise to 100 if the team prefers, but enforce one).
- **Monorepo (optional):** `melos` only when there are multiple packages. Single-app repos skip it.

## Run

- Install: `flutter pub get` (or `fvm flutter pub get`).
- Codegen (watch): `dart run build_runner watch --delete-conflicting-outputs`
- Codegen (one shot): `dart run build_runner build --delete-conflicting-outputs`
- Run: `flutter run -d <device>` (`flutter devices` to list; common: `chrome`, `macos`, simulator UDID).
- Run with env: `flutter run --dart-define-from-file=env/dev.json`
- Tests: `flutter test` (unit + widget). One file: `flutter test test/features/auth/login_test.dart`. Integration: `flutter test integration_test/`.
- Format: `dart format .` Lint: `dart analyze` (must be clean to merge).
- Build: `flutter build apk --release`, `flutter build ios --release --no-codesign`, `flutter build web`.

Expected runtimes: `pub get` ≤30s warm, codegen full ≤45s, hot reload <1s, full `flutter test` ≤2m for a mid-size app. First Android build adds Gradle warmup; budget 3 minutes.

## Architecture

Feature-first, not layer-first.

```
lib/
├── main.dart                       # ProviderScope wraps the root.
├── app.dart                        # MaterialApp.router wired to go_router.
├── core/
│   ├── theme/                      # ThemeData, ColorScheme, typography.
│   ├── router/                     # GoRouter config + route guards.
│   ├── network/                    # Dio or http client, interceptors, error mapping.
│   └── widgets/                    # Truly app-wide widgets (e.g. ErrorScreen).
├── features/
│   ├── auth/
│   │   ├── data/                   # Repositories, remote/local data sources.
│   │   ├── domain/                 # Entities, value objects. No Flutter imports.
│   │   ├── presentation/           # Screens, widgets specific to auth.
│   │   └── providers.dart          # Riverpod providers for this feature.
│   └── posts/                      # Same shape as auth/.
├── shared/                         # Cross-feature widgets and utilities.
└── db/
    ├── database.dart               # @DriftDatabase, generated companion.
    ├── tables/                     # @DataClassName table classes.
    └── daos/                       # @DriftAccessor classes, one per aggregate.

test/
├── unit/                           # Pure-Dart, no Flutter binding.
├── widget/                         # WidgetTester. Mirrors lib/features structure.
└── golden/                         # Golden-file tests for visual regression.
integration_test/                   # End-to-end on a real device or emulator.
```

The `domain/` layer never imports `package:flutter/*`. Push Flutter types out of business logic.

## Conventions

- **State:** every provider is generated via `@riverpod`. `Notifier`, `AsyncNotifier`, and family variants follow. No global `final fooProvider = Provider(...)` in new code.
- **Codegen:** run `build_runner watch` during active work. CI runs the one-shot variant and fails if anything is out of date.
- **Immutability:** `final` everywhere. Data classes via `freezed` or Drift's generated `DataClass`. No mutable public fields.
- **Async:** every async function returns `Future<T>` or `Stream<T>` explicitly. No `async` without `await` in the body.
- **BuildContext:** never used after an `await` without a `mounted` check. The linter flags it; do not silence the rule.
- **Routing:** typed routes via `go_router_builder`. No string concatenation for paths.
- **Widget composition:** prefer many small widgets over one giant `build` method. Extract anything over ~30 lines into a named widget or a private `_Foo` widget in the same file.
- **Naming:** `snake_case.dart` for files, `PascalCase` for classes, `lowerCamelCase` for members.

## Tests

- **Where:** `test/` mirrors `lib/`. Widget tests under `test/widget/`, unit under `test/unit/`. Integration under `integration_test/`.
- **Run one file:** `flutter test test/features/auth/login_test.dart`. Filter: `--name "logs in"`.
- **Widgets:** `testWidgets('description', (tester) async { ... })` with `tester.pumpWidget(ProviderScope(overrides: [...], child: ...))`. Override providers, never reach into globals.
- **Riverpod:** override providers with fakes via `ProviderScope(overrides: [foo.overrideWith(() => FakeFoo())])`. Read state in tests via `container.read(...)`.
- **Drift:** in tests, construct the database with `NativeDatabase.memory()`. Never point tests at a file-backed DB.
- **Mock policy:** HTTP via `mocktail` or a fake `Dio` adapter (`DioAdapter`). Time via `fake_async`. Never mock generated Riverpod providers; override them.
- **Golden tests:** keep them small (a handful) and update intentionally with `--update-goldens`.

## External APIs

Three patterns for auth-bound third-party APIs (Firebase, Stripe, Auth0, Mapbox, and similar):

1. **`--dart-define-from-file=env/<stage>.json`.** Flutter 3.7+ supports a JSON env file at build time; values read via `String.fromEnvironment(...)`. Flutter-native, no extra package.
2. **`envied` package.** Generates a typed env class from a `.env` file at build time. More ergonomic, adds codegen.
3. **Authsome.** Useful when the Flutter app calls a backend you also build; the backend uses Authsome and the client just speaks to your API with a session token. See [authsome.dev](https://authsome.dev). For keys consumed directly on-device (Firebase API key, Mapbox token), options 1 and 2 fit better.

Pick one. Hard-coded keys in `lib/` is the standard regret.

## Don't

- Don't use `setState` once a screen has more than two pieces of state. Move to a `Notifier`.
- Don't fetch in `initState`. Use a `FutureProvider` or `AsyncNotifier` and let the widget rebuild.
- Don't block the main isolate with heavy compute. Use `compute()` for one-off CPU work or `Isolate.run` for longer tasks.
- Don't use `BuildContext` after an `await` without `if (!mounted) return;`. The widget may be gone.
- Don't ignore `dart analyze` warnings. Treat them as errors in CI.
- Don't ship a `print(...)` call. Use `debugPrint` and gate behind `kDebugMode`, or wire a real logger.
- Don't commit generated files (`*.g.dart`, `*.freezed.dart`, `*.drift.dart`) without rerunning codegen first. CI catches stale output.
- Don't paginate by `OFFSET` against Drift when row count grows. Use a keyset (`WHERE id < ? LIMIT 20` ordered desc).
